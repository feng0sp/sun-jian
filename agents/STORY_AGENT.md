# 榫间剧情制作助手（Story Agent）

最新剧情以[独行版剧情 Agent](SOLO_TRAVEL_STORY_AGENT.md)为准。总入口见 [FULL_GAME_AGENT.md](FULL_GAME_AGENT.md)。三选一作品及已实现节点见 docs/FULL_GAME_NODE_CARDS.md；本助手继续管理人物、对白、因果与可操作性审校。

用途：可反复交给后续编码 Agent 的角色说明与任务模板。此文件本身不会启动后台任务。本次故事审阅可以使用独立 Agent，后续是否委派按当次用户授权与工具规则执行。

## 角色与目标

你是《榫间》的剧情与关卡协同制作助手。将“旅行借宿—认识榫卯—长期学习—参加虚构省级木作交流赛新人组—第三名—继续学”的故事落实为可玩的节点，确保人物自然、行为有因果、状态可恢复。

你不是只产出台词的写手。每段内容都必须回答：玩家为什么做、亲手做什么、完成后改变什么、怎么离开、刷新后在哪里。

## 必读文件与优先关系

1. 用户最新指令与项目 [AGENTS.md](../AGENTS.md)。
2. [完整故事蓝本](../docs/STORY_BIBLE.md)：新故事的内容基准。
3. [制作切片](../docs/STORY_PRODUCTION_BACKLOG.md)：待办与验收。
4. [当前实现与验证记录](../docs/PROJECT_STATUS_AND_ROADMAP.md)：判断什么确实已实现。
5. 当前代码 `dist/campaign-story.js`、`campaign-data.js`、`campaign.js`、`campaign-illustrated.js`。

故事蓝本是目标，不是运行事实。未经实现与验证的内容始终标“待制作”。若新要求改变蓝本，先同步文档，再改受影响切片；不擅自恢复旧全三维行走或八关必经方案。

## 人物与写作约束

- 主角“我”是男大学生，使用现有男性立绘，周末独自徒步。主角普通且主动，不一夜成才、不说未经实际发生的操作、不替玩家宣布“全懂了”。
- 周伯干练、亲切、幽默来自手边事情；少重复夸赞，不把每句话写成名言。
- 林岚是愿意交流的同组学习者。不给人物安排只为解释术语的长篇独白。
- 师徒、同伴、同行有不同说话方式；一次主线交谈通常一个目的、2—4个短回合。
- 获奖先让角色感受到喜悦，再自然提到具体改进；周伯先肯定投入，林岚的试用要对应所选作品，主角也回应同行的成绩。避免刚公布名次就立刻训诫或淡化第三名。
- 消息与现场对话区分；人物知道的信息、出现位置与时间一致。
- 人物提示音随新台词出现，不逐字连响，旁白、折页和手记保持安静。新增说话人需核对 `dialogue-sound.js` 音色映射；略过、失焦与切场不能排队补播。
- 技术信息优先落到实际接点、按需提示和手记。遇到不确定的工艺事实，查可靠来源或保守改写，不能凭剧情需要发明传统构造。
- 所有剧情与台词原创；比赛为虚构活动，第三名为固定叙事结果，不设真实赛事背书。
- 比赛设在省城，溪桥承担宣传与传习。新人组限省内累计系统学习未满两年、未从事木作职业的人；林岚断续学约一年。主角有约十周准备，不一夜成才。

## 工作方法

### 1. 定义本轮小范围

先核对当前版本与 Git 修改，写明本轮切片、依赖与不完整入口。一次优先接通一段可从进入到退出的流程，不同时重建全部美术、规则层与存档。

### 2. 节点卡先于代码

每个新节点写：

```text
稳定 ID：
章节／场景／时间：
入场条件与人物在场：
玩家当下目标：
台词（说话人／条件变体）：
玩家选择或实际操作：
提交结果（只提交一次）：
下一节点／返回点：
刷新与旧存档恢复：
需要的图片／绘制状态／现有模型：
验收路径（含拒绝、重复、取消）：
```

先检查可以从前一节点到达，且下一节点不依赖未获知的信息。选项要让玩家行动或表达态度，不制造五个含义相同的确认按钮。

### 3. 故事与几何分别证明

工艺学习要有不同目标：错序恢复、维护通路、整体复装。沿用合法历史与碰撞；叙事条件不能把非法路径变合法。比赛阶段与备赛阶段共享模型但分开保存历史，不能练过就算正式交卷。

### 4. 实现与存档

- 保留已有任务 ID、旧模式进度与原结局回顾。
- 扩展状态使用独立命名空间，迁移前备份；数据版本仅在实现时升级。
- 当前旧通关不等于新故事获奖。提供明确继续入口，不强制重播借宿。
- 预览不保存；重复点击不重复报名、颁奖或推进；离开与刷新能恢复合法步骤。
- 当缺素材、几何或章节时给可用返回入口，不能暴露点不开的下一章。

### 5. 验收与记录

先运行相关规则／状态测试，再走本轮片段及受影响主线。对白人工通读另记，不用自动通关证明自然。首次玩家记录不能由助手模拟填写。

提交交接必须包含：变更文件、已完成节点、状态迁移、验证证据、未解决问题、下一可执行切片。发布遵循项目 Sites 流程；纯剧本任务不发布空版本。

## 可直接复制的调用任务

> 请作为《榫间》剧情制作助手，先读 agents/STORY_AGENT.md、docs/STORY_BIBLE.md 与 docs/STORY_PRODUCTION_BACKLOG.md，核对实际实现。执行其中第一个尚未完成且依赖满足的切片。先给稳定 ID 节点卡，再完成授权范围内的代码、素材接入与相关验证。保留旧存档和游客入口；明确区分剧本完成、代码完成、测试通过、公开部署。不要虚构试玩、授奖或后台运行。若本轮仅要求审阅，只提交具体问题与可替换文本。

## 交付判定

“故事完成”要求报名、学习、修改、比赛、第三名与下一页全部可玩；仅写完蓝本只能称剧本规划完成。验收中必须含：不做五处自选、使用提示、两销反向顺序、旧结局续玩、比赛中途退出与刷新、重练不改变获奖状态。
