# 0.13.9 情景木构模型

日期 2026-11-06。三套原创示教几何直接注册到 JointPuzzle.LEVELS，分类为 campaign，均由可见实体共用连续碰撞数据。本文件只记录模型与验证；主流程接入、绘制状态和旧存档迁移由旅程控制层负责。

## 接入契约

在 puzzle-core.js 之后、game.js 和 campaign-data.js 之前加载 dist/context-puzzles.js。浏览器公开 ContextPuzzles.levels；Node 可 require 该模块。三套均使用现有材质、倒角与自动取景，无外部模型资源。

| 关卡 ID | 固定构件 | 可动构件 | 初始合法路径 |
|---|---|---|---|
| chair-rail-joint | leg 示教椅腿 | tenon 长横枨 | tenon 沿 X+，合回沿 X− |
| offcut-corner-lap | 无 | lower 横向试配料、upper 竖向试配料 | lower 可 Y−、X−、Z−；upper 可 Y+、X+、Z+。任一先取均可继续完成 |
| store-door-latch | door 门板、导座及右止口 | pin 宽木钥、tenon 长横闩 | pin 沿 Z+；之后 tenon 沿 X−。逆序沿 X+、Z− 合回 |

库门故意沿用 pin 与 tenon 的内部 piece ID，方便上层验证旧穿销中 pin/Z+ 的对应操作。旧样木 tenon/Y+ 与新门闩 tenon/X− 含义不同，不能直接把旧方向换成新方向当作玩家已操作；旧合法完成记录可由控制层按任务身份兼容。

## 构造

- 椅枨采用单独的同形试配件。固定椅腿上是带内侧止口的盲卯，长横枨收成较窄的榫，外侧宽肩贴腿侧。卯壁实际限制上下、前后，内侧止口实际限制反向移动。
- L 形转角用两根宽料，缺口位于端部，各让一层。两件体量接近，接触面宽，不增加锁销；两种先后和不同合法直线退出方向均受规则验证。
- 库门固定板托住三个导座。中央导座和横闩都有与宽木钥一致的通孔，木钥留在孔中时真实阻挡横闩。右侧可见止口使左侧成为横闩退出方向。两端导座限制横闩抬起或前后脱出。
- 每块木件由连通实心体构成。固定门板与各导座、止口也通过门板连在一起。宽木钥有明显露头，保持抓取面积。

这些是为游戏制作的示教组合。结构说明只描述当前实体形状和约束，不称为某件古物或所有传统椅子的通用制式。

## 规则与画面验证

运行 node tests/context-puzzles.test.cjs，结果写入 output/context-0139/geometry/verification.json。

- 椅枨 2 个、端部搭接 4 个、库门 3 个可达拆解状态，全部可完成，初始无穿插。
- 每次实际抽出都可沿原路反向装入，插入预览在合法全行程才允许归位。
- 全散件装配可完成；提前装入库门木钥会实际挡住横闩，该木钥仍可沿 Z+ 取回。
- 三套所有木件连通、表面顶点有限，倒角网格可生成。
- 九张独立 Three.js 实绘图覆盖默认、反侧视角和拆开状态。使用现有 WoodMesh、WoodFinish 与游戏默认取景公式；没有将小模型贴到全景插画。
- 1000×720 操作区默认视角下，椅枨的真实抽出行程约 110 像素；库门横闩在取钥后需要约 354 像素横移，起终点均在画面内。实际规则行程分别约 1.5 与 7.97 个结构单位。

画面与投影数据见 output/context-0139/geometry/visual-verification.json；原始三维视图为同目录的各关卡 default、rotate、open PNG。该独立视图验证模型轮廓和取景，上层仍须通过主入口测试实际指针、返回及存档。
